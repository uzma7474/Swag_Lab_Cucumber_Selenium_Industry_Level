1. DriverManager.java

Location: src/main/java/driver/DriverManager.java

This is the central place from which the framework obtains the current browser instance.

I recommend ThreadLocal<WebDriver> even if you're initially running tests sequentially. 
It makes the framework ready for parallel execution later.
----------------------------------------------------------------------------------------------------------
Q. Why ThreadLocal?

Without ThreadLocal:

private static WebDriver driver;

parallel execution can cause:

Test A → Chrome A
Test B → Chrome B
        ↓
Both tests can accidentally access the wrong driver

With ThreadLocal:

Thread 1 → WebDriver 1
Thread 2 → WebDriver 2
Thread 3 → WebDriver 3

So this is a better framework design.

---------------------------------------------------------------------------------------------------------
2. DriverFactory.java

Location: src/main/java/driver/DriverFactory.java

The factory is responsible for creating the browser.

3. BasePage.java

Location: src/main/java/base/BasePage.java

This is one of the most important classes in the framework.

It should contain generic Selenium functionality, not SauceDemo-specific functionality.

For example, this belongs here:

click(element);
type(element, text);
getText(element);
waitForVisible(element);
waitForClickable(element);

But this does not belong here:

login();
addBackpackToCart();
checkout();

4. BaseTest.java

Location: src/main/java/base/BaseTest.java

There is an architectural point here.

Because you're building a Cucumber + TestNG framework, Cucumber's Hooks should normally control browser lifecycle for Cucumber scenarios.

Therefore, BaseTest should not create another browser independently of the Cucumber hooks.

Instead, make BaseTest a reusable base class for any direct TestNG tests you may add later.
